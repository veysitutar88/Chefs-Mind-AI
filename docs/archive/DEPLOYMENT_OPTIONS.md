# Сравнение вариантов развертывания Frontend

На основе анализа кодовой базы `frontend-enhanced` предлагаются два основных варианта развертывания в production.

---

## Вариант 1: Платформа Vercel

Vercel — это PaaS (Platform as a Service) от создателей Next.js, предоставляющая оптимизированную среду для хостинга Next.js приложений.

| Критерий | Оценка | Комментарий |
| :--- | :--- | :--- |
| **Стоимость** | Низкая (есть бесплатный тариф) | Бесплатный тариф "Hobby" отлично подходит для разработки и небольших проектов. Платные тарифы "Pro" начинаются от $20/мес. на пользователя. |
| **Масштабируемость** | Высокая | Автоматическое масштабирование "из коробки". Глобальная сеть CDN (Edge Network) для быстрой доставки контента по всему миру. |
| **Сложность настройки** | Очень низкая | Практически нулевая конфигурация. Достаточно подключить Git-репозиторий. Vercel автоматически определяет, что это Next.js проект, и настраивает сборку и развертывание. |
| **Производительность** | Очень высокая | Оптимизации для Next.js, включая SSR, SSG, ISR, Edge Functions. Глобальный CDN обеспечивает минимальную задержку для пользователей. |

**Плюсы:**
*   Простота и скорость развертывания.
*   Автоматические превью-сборки для каждого Pull Request.
*   Встроенная аналитика.
*   Высокая производительность без дополнительной настройки.

**Минусы:**
*   Меньше гибкости и контроля над инфраструктурой по сравнению с Docker.
*   Стоимость может расти с увеличением команды и трафика.

---

## Вариант 2: Docker-контейнер на облачном провайдере (AWS, GCP, Azure)

Этот подход заключается в сборке Docker-образа и его развертывании на любом облачном хостинге, поддерживающем контейнеры (например, AWS ECS, Google Cloud Run, Azure Container Apps).

| Критерий | Оценка | Комментарий |
| :--- | :--- | :--- |
| **Стоимость** | Варьируется (от низкой до высокой) | Стоимость зависит от выбранного провайдера и используемых ресурсов (CPU, память). Может быть дешевле Vercel на больших масштабах, но требует более точного планирования. |
| **Масштабируемость** | Очень высокая | Полный контроль над конфигурацией автомасштабирования. Можно настроить очень гибкие правила. |
| **Сложность настройки** | Средняя / Высокая | Требуется настройка CI/CD пайплайна для сборки и публикации Docker-образа, а также конфигурация облачной инфраструктуры (сеть, балансировщики, оркестрация контейнеров). |
| **Производительность** | Высокая | Производительность сильно зависит от правильной конфигурации инфраструктуры (например, настройка CDN). Можно достичь очень высоких показателей, но это требует экспертизы. |

**Плюсы:**
*   Максимальная гибкость и контроль над окружением.
*   Возможность унифицировать стек развертывания (если бэкенд тоже работает в Docker).
*   Независимость от конкретной платформы (вендор-лок).

**Минусы:**
*   Значительно сложнее в настройке и поддержке.
*   Требует больше времени и ресурсов на DevOps.
*   Отсутствие автоматических превью-сборок "из коробки".

**Version:** v2.1.6  
**Last Updated:** November 19, 2025  
**Purpose:** Полное текстовое описание системы маршрутизации агентов без кода

## 1. Обзор системы

Chef's Mind AI использует мультиагентную архитектуру с центральным оркестратором для интеллектуальной маршрутизации запросов пользователей. Система состоит из пяти специализированных агентов, каждый из которых отвечает за свою область ресторанного бизнеса.

### Философия дизайна

- **Единая точка входа**: Пользователь общается через универсальный чат, система сама определяет нужного агента
- **Специализация**: Каждый агент — эксперт в своей области с доступом к релевантным данным
- **Прозрачность**: Пользователь видит, какой агент отвечает, и может явно выбрать агента через UI
- **Качество**: Все ответы проходят через QA-Gate для защиты от галлюцинаций
- **Гибкость**: Система поддерживает mixed-intent запросы с привлечением нескольких агентов

## 2. Описание агентов

### 2.1. Универсальный чат (Main Chat / Chef's Mind AI)

**Назначение:** Главная точка входа для всех запросов пользователя.

**Характеристики:**
- Не является отдельным агентом, а служит интерфейсом к оркестратору
- Автоматически определяет intent и маршрутизирует к нужному агенту
- Поддерживает загрузку документов (чеки, накладные, фото) для автоматической обработки
- Сохраняет контекст диалога для multi-turn conversations

**Доступ к данным:**
- Read: все таблицы (для анализа контекста)
- Write: `chat_sessions`, `chat_messages`


### 2.2. AI Sous-Chef (Chef Agent)

**Назначение:** Специалист по кухонным операциям, рецептам и меню.

**Зона ответственности:**
- Создание и адаптация рецептов
- Планирование меню (дневное, недельное, сезонное)
- Управление остатками и их использование
- Расчёт порций и выхода блюд
- Техкарты и стандарты приготовления
- Подготовка к сервису (mise en place)
- Советы по технике приготовления

**Типичные задачи:**
- "Составь меню на неделю из имеющихся продуктов"
- "Как приготовить борщ на 50 порций?"
- "Что можно сделать из остатков курицы и овощей?"
- "Адаптируй этот рецепт под веганскую версию"
- "Рассчитай выход блюда для банкета на 100 человек"

**Доступ к данным:**
- Read: `recipes`, `ingredients`, `inventory`, `menu_items`, `suppliers` (для проверки доступности)
- Write: `recipes`, `menu_items`, `production_plans`

---

### 2.3. AI Brain-Chef (Accountant Agent)

**Назначение:** Финансовый аналитик и специалист по учёту.

**Зона ответственности:**
- Расчёт себестоимости блюд (food cost)
- Управление заказами и поставщиками
- Ценообразование и маржинальность
- Контроль затрат и бюджетирование
- Финансовые отчёты и аналитика
- Планирование закупок
- Инвентаризация и списания

**Типичные задачи:**
- "Рассчитай себестоимость этого рецепта"
- "Какая прибыль с этого блюда при цене 500 руб?"
- "Создай заказ у поставщика на неделю"
- "Покажи топ-5 самых дорогих ингредиентов"
- "Сколько мы потратили на мясо в этом месяце?"

**Доступ к данным:**
- Read: `recipes`, `ingredients`, `suppliers`, `orders`, `inventory`, `menu_items`, `financial_reports`
- Write: `orders`, `suppliers`, `financial_reports`, `cost_calculations`


---

### 2.4. AI Research (Researcher Agent)

**Назначение:** Исследователь рынка и внешний аналитик.

**Зона ответственности:**
- Поиск информации о трендах в ресторанном бизнесе
- Анализ конкурентов и рынка
- Поиск новых поставщиков и ингредиентов
- Исследование техник и оборудования
- Статистика и отраслевые данные
- Поиск рецептур и кулинарных техник
- Маркетинговые исследования

**Типичные задачи:**
- "Какие тренды в food-индустрии сейчас актуальны?"
- "Найди поставщиков органических овощей в Москве"
- "Проанализируй меню конкурентов в нашем районе"
- "Какое оборудование лучше для sous-vide?"
- "Статистика популярности веганских блюд в 2025"

**Доступ к данным:**
- Read: `suppliers`, `market_data`, `competitors`, `trends`
- Write: `research_reports`, `market_data`
- External: Интеграция с поисковыми API (Perplexity-style)

---

### 2.5. AI Media-Studio (Media Agent)

**Назначение:** Генерация визуального контента для маркетинга и меню.

**Зона ответственности:**
- Генерация изображений блюд (food photography)
- Создание видео-рецептов и промо-роликов
- Улучшение промптов (Prompt Enhancer)
- Управление библиотекой медиа-ассетов
- Оформление меню и маркетинговых материалов
- Адаптация контента под разные платформы

**Типичные задачи:**
- "Создай фото этого блюда для Instagram"
- "Сгенерируй видео приготовления пасты карбонара"
- "Сделай изображение для меню — стейк с овощами"
- "Создай промо-баннер для летнего меню"
- "Оформи визуал для доставки"

**Доступ к данным:**
- Read: `recipes`, `menu_items`, `media_assets`
- Write: `media_assets`, `media_jobs`
- External: Интеграция с Imagen, Veo, DALL·E, другими генеративными моделями


---

### 2.6. QA-Gate (Quality Agent)

**Назначение:** Внутренний проверочный слой для контроля качества ответов.

**Зона ответственности:**
- Проверка ответов на адекватность и корректность
- Защита от галлюцинаций AI-моделей
- Валидация данных (цены, количества, расчёты)
- Проверка соответствия стандартам и правилам
- Автоматическая коррекция очевидных ошибок
- Scoring качества ответов

**Характеристики:**
- Не отображается в UI как отдельный агент
- Работает как middleware для всех ответов
- Может блокировать или корректировать ответы других агентов
- Логирует все проверки для аудита

**Типичные проверки:**
- Математические расчёты (себестоимость, порции)
- Реалистичность данных (цены, время приготовления)
- Соответствие рецептов кулинарным стандартам
- Безопасность (аллергены, температурные режимы)
- Консистентность с базой данных

**Доступ к данным:**
- Read: все таблицы (для валидации)
- Write: `qa_logs`, `corrections_history`

### Обработка Mixed-Intent запросов

Когда запрос содержит несколько намерений (например, "меню + прибыль"), оркестратор:

1. **Определяет все intent'ы** в запросе с весами
2. **Выбирает Primary Agent** по наивысшему весу
3. **Создаёт sub-tasks** для Secondary Agent(s)
4. **Координирует выполнение:**
   - Primary Agent получает основной запрос
   - Secondary Agent(s) выполняют вспомогательные задачи
   - Primary Agent объединяет результаты в финальный ответ
5. **QA-Gate проверяет** итоговый ответ на консистентность

**Пример:**
- Запрос: "Составь меню на неделю и рассчитай прибыль"
- Intent 1: `cooking/menu` (вес 2.0) → AI Sous-Chef
- Intent 2: `finance/costing` (вес 2.5) → AI Brain-Chef
- Решение: Primary = AI Brain-Chef (выше вес), Secondary = AI Sous-Chef
- Выполнение:
  1. AI Sous-Chef создаёт меню на неделю
  2. AI Brain-Chef получает меню и рассчитывает прибыль по каждому блюду
  3. AI Brain-Chef формирует итоговый ответ с меню + финансами
  4. QA-Gate проверяет корректность расчётов

## 4. Логика оркестратора

### 4.1. Определение Intent

Оркестратор использует **keyword-based классификацию** с весовыми коэффициентами:

**Процесс:**
1. Нормализация входного текста (lowercase, trim)
2. Проверка кэша последних 3 запросов (similarity > 0.8)
3. Если не в кэше — анализ по паттернам ключевых слов
4. Подсчёт score для каждого intent'а:
   - Базовый score = количество совпадений × вес паттерна
   - Бонус за множественные совпадения = count × 0.2
   - Бонус для cooking/finance (domain-specific) = +0.1 к confidence
5. Выбор intent'а с максимальным score
6. Расчёт confidence (0.0 - 1.0)

**Веса паттернов (по приоритету):**
- Media: 3.0 (максимальный — чёткие команды генерации)
- Finance: 2.5 (высокий — специфичные финансовые термины)
- Cooking: 2.0 (средний — широкая область)
- Research: 1.8 (средний — исследовательские задачи)
- QA: 0.5 (минимальный — fallback для неопределённых запросов)

**Примеры ключевых слов:**
- Cooking: "рецепт", "приготовить", "ингредиенты", "меню", "блюдо"
- Finance: "себестоимость", "затраты", "прибыль", "цена", "расчет"
- Research: "исследовать", "анализ", "тренды", "рынок", "конкуренты"
- Media: "создай видео", "сгенерируй изображение", "фото", "видео"
- QA: "что такое", "как выбрать", "качество", "стандарт"


### 4.2. Выбор основного агента

После определения intent оркестратор:

1. **Маппинг intent → agent:**
   - `cooking` → AI Sous-Chef
   - `finance` → AI Brain-Chef
   - `research` → AI Research
   - `media` → AI Media-Studio
   - `qa` → QA-Gate

2. **Проверка доступности агента** (health check)

3. **Передача контекста:**
   - История диалога (последние N сообщений)
   - Метаданные пользователя (роль, права доступа)
   - Релевантные данные из БД

4. **Установка таймаута** для ответа агента

### 4.3. Создание sub-tasks для вторичных агентов

Когда обнаружено несколько intent'ов:

1. **Декомпозиция запроса:**
   - Разбивка на независимые подзадачи
   - Определение зависимостей между задачами

2. **Параллельное выполнение** (где возможно):
   - Независимые задачи выполняются одновременно
   - Зависимые задачи — последовательно

3. **Агрегация результатов:**
   - Primary Agent получает результаты от Secondary
   - Формирует единый связный ответ
   - Разрешает конфликты данных (если есть)

**Пример декомпозиции:**
- Запрос: "Создай меню с фото и рассчитай прибыль"
- Sub-task 1: AI Sous-Chef → создать меню
- Sub-task 2: AI Media-Studio → сгенерировать фото (зависит от Sub-task 1)
- Sub-task 3: AI Brain-Chef → рассчитать прибыль (зависит от Sub-task 1)
- Порядок: 1 → (2 || 3) → агрегация

### 4.4. Подключение QA-Gate

QA-Gate работает как **middleware** и активируется:

**Всегда:**
- После каждого ответа любого агента
- Перед отправкой ответа пользователю

**Процесс проверки:**
1. **Структурная валидация:**
   - Наличие обязательных полей
   - Корректность формата данных

2. **Семантическая проверка:**
   - Соответствие ответа вопросу
   - Отсутствие противоречий
   - Реалистичность данных

3. **Доменная валидация:**
   - Для финансов: проверка расчётов, реалистичность цен
   - Для рецептов: корректность пропорций, времени приготовления
   - Для медиа: соответствие промпта результату

4. **Scoring (0.0 - 1.0):**
   - 0.9-1.0: отличный ответ, без корректировок
   - 0.7-0.9: хороший ответ, возможны минорные правки
   - 0.5-0.7: приемлемый ответ, требуются корректировки
   - < 0.5: плохой ответ, блокируется или переделывается

5. **Действия:**
   - Score ≥ 0.7: пропустить ответ
   - Score 0.5-0.7: применить автокоррекцию
   - Score < 0.5: запросить новый ответ у агента или вернуть fallback

6. **Логирование:**
   - Все проверки записываются в `qa_logs`
   - Корректировки сохраняются в `corrections_history`

## 5. Примеры маршрутизации

### Пример 1: "Сделай меню на неделю из остатков и посчитай прибыль"

**Анализ запроса:**
- Ключевые слова: "меню", "неделю", "остатков", "посчитай", "прибыль"
- Intent 1: `cooking/menu` (вес 2.0, keywords: "меню", "остатков")
- Intent 2: `finance/costing` (вес 2.5, keywords: "посчитай", "прибыль")
- Confidence: 0.85 (высокая, чёткие ключевые слова)

**Маршрутизация:**
1. **Primary Agent:** AI Brain-Chef (finance имеет больший вес 2.5)
2. **Secondary Agent:** AI Sous-Chef (для создания меню)

**Порядок выполнения:**
1. **AI Sous-Chef** (sub-task):
   - Запрос к БД: `inventory` (текущие остатки)
   - Запрос к БД: `recipes` (доступные рецепты)
   - Создаёт меню на 7 дней, используя имеющиеся продукты
   - Возвращает: список блюд с ингредиентами

2. **AI Brain-Chef** (primary):
   - Получает меню от AI Sous-Chef
   - Запрос к БД: `suppliers`, `orders` (цены на ингредиенты)
   - Рассчитывает себестоимость каждого блюда
   - Запрос к БД: `menu_items` (цены продажи)
   - Рассчитывает прибыль по каждому блюду и общую за неделю
   - Формирует итоговый ответ: меню + финансовая сводка

3. **QA-Gate:**
   - Проверяет математику расчётов (себестоимость, прибыль)
   - Валидирует реалистичность цен
   - Проверяет, что все блюда из меню действительно можно приготовить из остатков
   - Проверяет консистентность: количество ингредиентов в меню ≤ остатки в inventory
   - Score: 0.92 (высокий)
   - Действие: пропустить без корректировок

**Итоговый ответ пользователю:**
```
[AI Brain-Chef]
Меню на неделю из имеющихся остатков:

Понедельник: Борщ (себестоимость 120₽, цена 350₽, прибыль 230₽)
Вторник: Паста карбонара (себестоимость 80₽, цена 280₽, прибыль 200₽)
...

Общая прибыль за неделю: 4,500₽
Food cost: 28%
```

### Пример 2: "Посчитай food cost для этих блюд"

**Анализ запроса:**
- Ключевые слова: "посчитай", "food cost", "блюд"
- Intent: `finance/costing` (вес 2.5)
- Confidence: 0.90 (очень высокая, явный финансовый запрос)

**Маршрутизация:**
1. **Primary Agent:** AI Brain-Chef
2. **Secondary Agent:** не требуется (чисто финансовая задача)

**Порядок выполнения:**
1. **AI Brain-Chef:**
   - Парсит контекст: какие блюда имеются в виду (из предыдущих сообщений или прикреплённого файла)
   - Запрос к БД: `recipes` (состав блюд)
   - Запрос к БД: `ingredients`, `suppliers` (цены на ингредиенты)
   - Рассчитывает себестоимость каждого ингредиента
   - Суммирует food cost для каждого блюда
   - Запрос к БД: `menu_items` (цены продажи)
   - Рассчитывает процент food cost от цены продажи

2. **QA-Gate:**
   - Проверяет корректность математических расчётов
   - Валидирует реалистичность food cost (обычно 25-35% для ресторанов)
   - Если food cost > 40% → предупреждение
   - Проверяет, что все ингредиенты из рецепта учтены
   - Score: 0.88
   - Действие: пропустить с минорным предупреждением о высоком food cost

**Итоговый ответ пользователю:**
```
[AI Brain-Chef]
Food cost анализ:

1. Борщ:
   - Себестоимость: 120₽
   - Цена продажи: 350₽
   - Food cost: 34%

2. Паста карбонара:
   - Себестоимость: 80₽
   - Цена продажи: 280₽
   - Food cost: 29%

⚠️ Рекомендация: Food cost борща немного высок (норма 25-30%).
Рассмотрите оптимизацию рецепта или повышение цены.
```

### Пример 3: "Сделай картинку для этого блюда и предложи цену продажи"

**Анализ запроса:**
- Ключевые слова: "сделай", "картинку", "блюда", "предложи", "цену"
- Intent 1: `media/image` (вес 3.0, keywords: "сделай", "картинку")
- Intent 2: `finance/pricing` (вес 2.5, keywords: "цену")
- Confidence: 0.88

**Маршрутизация:**
1. **Primary Agent:** AI Media-Studio (media имеет наивысший вес 3.0)
2. **Secondary Agent:** AI Brain-Chef (для расчёта цены)

**Порядок выполнения:**
1. **AI Sous-Chef** (неявный sub-task):
   - Если "это блюдо" не определено явно, запрашивает контекст
   - Запрос к БД: `recipes` (получить детали блюда)
   - Возвращает: название, ингредиенты, описание

2. **AI Media-Studio** (primary):
   - Получает описание блюда
   - **Prompt Enhancer:** улучшает промпт для генерации
     - Базовый: "картинка блюда X"
     - Улучшенный: "Professional food photography of X, plated elegantly on white ceramic, natural lighting, shallow depth of field, garnished with fresh herbs, restaurant quality, 4K"
   - Выбирает провайдер (DALL·E, Imagen) на основе типа блюда
   - Создаёт задачу генерации: `media_jobs`
   - Генерирует изображение
   - Сохраняет в БД: `media_assets`

3. **AI Brain-Chef** (secondary, параллельно):
   - Запрос к БД: `recipes`, `ingredients`, `suppliers`
   - Рассчитывает себестоимость блюда
   - Анализирует рынок (средние цены на похожие блюда)
   - Применяет стандартную наценку (обычно 3-4x от себестоимости)
   - Предлагает диапазон цен с обоснованием

4. **Агрегация результатов:**
   - AI Media-Studio объединяет изображение + ценовые рекомендации
   - Формирует единый ответ

5. **QA-Gate:**
   - Проверяет, что изображение соответствует описанию блюда
   - Валидирует реалистичность предложенной цены
   - Проверяет, что наценка в разумных пределах (2.5x - 4.5x)
   - Score: 0.85
   - Действие: пропустить

**Итоговый ответ пользователю:**
```
[AI Media-Studio]
✅ Изображение создано!

[Показывается сгенерированное фото блюда]

Рекомендации по цене от AI Brain-Chef:
- Себестоимость: 150₽
- Рекомендуемая цена: 520₽ (наценка 3.5x)
- Диапазон: 480-580₽

Обоснование: Средняя цена похожих блюд в вашем сегменте — 500-550₽.
При цене 520₽ ваш food cost составит 29%, что оптимально.
```

## 6. Краткое резюме и различия агентов

### AI Sous-Chef vs AI Brain-Chef

**AI Sous-Chef (кухня):**
- Фокус: **КАК** готовить, **ЧТО** готовить
- Работает с: рецептами, техниками, меню, остатками
- Думает категориями: вкус, текстура, сочетания, порции
- Типичный вопрос: "Как приготовить?" / "Что приготовить?"
- Выход: рецепты, меню, техкарты, планы производства

**AI Brain-Chef (финансы):**
- Фокус: **СКОЛЬКО** стоит, **ВЫГОДНО** ли
- Работает с: ценами, затратами, прибылью, заказами
- Думает категориями: деньги, маржа, ROI, оптимизация
- Типичный вопрос: "Сколько стоит?" / "Какая прибыль?"
- Выход: расчёты, отчёты, заказы, финансовая аналитика

**Когда они работают вместе:**
- Sous-Chef создаёт рецепт → Brain-Chef считает его стоимость
- Brain-Chef видит высокий food cost → Sous-Chef оптимизирует рецепт
- Sous-Chef планирует меню → Brain-Chef проверяет рентабельность

---

### AI Research vs AI Brain-Chef

**AI Research (внешний поиск):**
- Фокус: информация **ВНЕ** системы
- Источники: интернет, базы данных, API, внешние источники
- Задачи: тренды, конкуренты, новые поставщики, техники
- Не имеет доступа к внутренним финансам
- Используется для: стратегических решений, исследований, обучения

**AI Brain-Chef (внутренний учёт):**
- Фокус: данные **ВНУТРИ** системы
- Источники: ваша БД (заказы, поставщики, финансы)
- Задачи: текущие операции, расчёты, отчёты
- Полный доступ к финансовым данным
- Используется для: операционных решений, учёта, контроля

**Когда использовать Research вместо Brain-Chef:**
- "Какие тренды в food-индустрии?" → Research
- "Сколько мы потратили на мясо?" → Brain-Chef
- "Найди новых поставщиков овощей" → Research
- "Создай заказ у текущего поставщика" → Brain-Chef
- "Что делают конкуренты?" → Research
- "Какая наша прибыль за месяц?" → Brain-Chef

---

### AI Media-Studio в общем потоке

**Роль Media-Studio:**
- **Визуализация** результатов работы других агентов
- **Маркетинг** — создание контента для продвижения
- **Презентация** — оформление меню, материалов

**Интеграция с другими агентами:**

1. **С AI Sous-Chef:**
   - Sous-Chef создаёт рецепт → Media-Studio делает фото блюда
   - Sous-Chef планирует меню → Media-Studio оформляет визуал меню
   - Sous-Chef описывает технику → Media-Studio создаёт видео-инструкцию

2. **С AI Brain-Chef:**
   - Brain-Chef рассчитывает прибыльные блюда → Media-Studio создаёт промо для них
   - Brain-Chef анализирует продажи → Media-Studio создаёт визуализацию данных
   - Brain-Chef предлагает цену → Media-Studio создаёт ценник/баннер

3. **С AI Research:**
   - Research находит тренды → Media-Studio создаёт контент по трендам
   - Research анализирует конкурентов → Media-Studio создаёт дифференцирующий визуал

**Уникальность Media-Studio:**
- Единственный агент, создающий **новый контент** (не анализирующий существующий)
- Работает с **внешними API** генеративных моделей
- Имеет **Prompt Enhancer** — уникальную функцию улучшения промптов
- Управляет **библиотекой ассетов** для переиспользования

**Типичный workflow:**
```
Запрос: "Создай летнее меню с фото"
↓
1. AI Sous-Chef: создаёт меню из сезонных продуктов
2. AI Brain-Chef: проверяет рентабельность блюд
3. AI Media-Studio: генерирует фото для каждого блюда
4. AI Media-Studio: оформляет финальное меню с ценами и фото
↓
QA-Gate: проверяет консистентность (фото соответствуют блюдам, цены корректны)
↓
Результат: готовое летнее меню с профессиональными фото
```

## 7. Технические детали оркестрации

### 7.1. Кэширование запросов

Оркестратор использует **легковесный кэш** для оптимизации:

**Параметры:**
- Размер: последние 3 запроса
- Алгоритм схожести: Левенштейн (Levenshtein Distance)
- Порог схожести: > 0.8 (80% совпадение)

**Логика:**
1. При новом запросе проверяется кэш
2. Если найден похожий запрос (similarity > 0.8):
   - Используется закэшированный intent
   - Confidence = 0.8 (фиксированный для кэша)
   - Пропускается классификация
3. Если не найден:
   - Выполняется полная классификация
   - Результат добавляется в кэш
   - Самый старый элемент удаляется (FIFO)

**Преимущества:**
- Ускорение повторяющихся запросов
- Снижение нагрузки на классификатор
- Консистентность для похожих формулировок

**Пример:**
```
Запрос 1: "Как приготовить борщ?"
→ Классификация → cooking → кэш

Запрос 2: "Как приготовить борщь?"  (опечатка)
→ Проверка кэша → similarity 0.95 → cooking (из кэша)
→ Классификация пропущена
```

---

### 7.2. Confidence и fallback

**Уровни Confidence:**
- **0.9-1.0:** Очень высокая уверенность — прямое выполнение
- **0.7-0.9:** Высокая уверенность — выполнение с логированием
- **0.5-0.7:** Средняя уверенность — выполнение + запрос подтверждения у пользователя
- **< 0.5:** Низкая уверенность — fallback на QA-Gate

**Fallback стратегия:**
1. Если confidence < 0.5:
   - Запрос направляется на QA-Gate
   - QA-Gate пытается уточнить намерение у пользователя
   - Или предлагает варианты интерпретации

2. Если агент недоступен (health check failed):
   - Попытка использовать резервного агента
   - Или возврат сообщения о недоступности

3. Если ответ агента некорректен (QA score < 0.5):
   - Повторный запрос к агенту с уточнением
   - Или fallback на другого агента
   - Максимум 2 попытки, затем — сообщение об ошибке

### 7.3. Контекст и память

**Типы контекста:**

1. **Session Context (краткосрочная память):**
   - Последние N сообщений в текущей сессии
   - Выбранный агент и intent предыдущих запросов
   - Загруженные файлы и документы
   - Хранится: в памяти + `chat_sessions`

2. **User Context (долгосрочная память):**
   - Предпочтения пользователя
   - Роль и права доступа
   - История взаимодействий
   - Хранится: `users`, `user_preferences`

3. **Domain Context (знания системы):**
   - Текущее состояние БД (остатки, заказы, меню)
   - Бизнес-правила и ограничения
   - Стандарты и нормативы
   - Хранится: все таблицы БД

**Передача контекста агентам:**
- Каждый агент получает релевантный контекст
- Фильтрация по правам доступа (RBAC)
- Ограничение размера контекста (token limit)

### 7.4. Мониторинг и метрики

**Собираемые метрики:**

1. **Routing Metrics:**
   - Распределение запросов по агентам
   - Среднее время классификации intent

2. **Agent Metrics:**

   - Частота использования агентов
   - Удовлетворённость ответами

**Эндпоинты мониторинга:**

## 8. Безопасность и ограничения

### 8.1. Контроль доступа (RBAC)

**Роли пользователей:**
- **Admin:** полный доступ ко всем агентам и данным
- **Manager:** доступ к финансам, отчётам, заказам
- **Chef:** доступ к рецептам, меню, производству
- **Staff:** ограниченный доступ (только чтение)

**Ограничения по агентам:**
- AI Brain-Chef: только Admin и Manager (финансовые данные)
- AI Sous-Chef: все роли (кулинарная информация)
- AI Research: все роли (публичная информация)
- AI Media-Studio: Chef, Manager, Admin (создание контента)
- QA-Gate: системный агент (не требует прав)

**Ограничения по данным:**
- Финансовые таблицы: только Admin и Manager
- Рецепты и меню: все роли (read), Chef+ (write)
- Заказы и поставщики: Manager+ (write)
- Медиа-ассеты: все роли (read), Chef+ (write)

### 8.2. Rate Limiting

**Ограничения по запросам:**
- Обычные пользователи: 60 запросов/минуту
- Premium пользователи: 120 запросов/минуту
- API ключи: 300 запросов/минуту

**Ограничения по агентам:**
- AI Media-Studio: 10 генераций/час (дорогие операции)
- AI Research: 30 запросов/час (внешние API)
- Остальные агенты: без специальных ограничений

### 8.3. SAFE_MODE

**Режим безопасности** для защиты от вредоносных запросов:

**Блокируемые действия:**
- Удаление критичных данных без подтверждения
- Массовые изменения финансовых записей
- Генерация неприемлемого контента (NSFW)
- SQL-инъекции и другие атаки

**Фильтры:**
- Input sanitization (очистка пользовательского ввода)
- Output validation (проверка ответов агентов)
- Content moderation (для Media-Studio)

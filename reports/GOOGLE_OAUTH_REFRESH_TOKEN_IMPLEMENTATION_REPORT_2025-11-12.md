## Механизм хранения refresh_token

### Шифрование
- **Алгоритм:** AES-256-CBC
- **Ключ:** Из переменной окружения `GOOGLE_OAUTH_ENCRYPTION_KEY`
- **Соль:** Статическая соль для генерации ключа
- **IV:** Случайный вектор инициализации для каждого шифрования

### База данных
- **Таблица:** `googleOAuthTokens`
- **Связь:** `userId` связывает токены с пользователями
- **Хранение:** Токены хранятся в зашифрованном виде
- **Метаданные:** Сохраняются Google ID и email для верификации

### Интеграция с Google OAuth
1. **Запрос refresh_token:** `access_type: 'offline'` + `prompt: 'consent'`
2. **Получение токенов:** После успешной аутентификации
3. **Шифрование:** Токены шифруются перед сохранением
4. **Сохранение:** Токены сохраняются в БД с метаданными пользователя
5. **Проверка статуса:** `/auth/google/status` проверяет наличие refresh_token

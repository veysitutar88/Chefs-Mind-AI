## Chef’s Mind AI — правила работы с MASTER_MANIFEST

> Этот документ обязателен для всех LLM-агентов (KiloCode, GPT, Gemini и т.д.), работающих с репозиторием **Chef’s Mind AI**.

---

## 1. Главный источник правды

Перед ЛЮБЫМИ действиями (анализ, рефакторинг, генерация кода, правки UI/бэкенда) агент обязан:

1. Прочитать файл:

   - `docs/MASTER_MANIFEST.json`
   - `docs/MASTER_CONTEXT_v2.1.4_UI-REFRESH.md`

2. Считать их **единственным источником правды** о:
   - структуре проекта;
   - актуальных блоках (Block0–Block5);
   - агентах и MCP;
   - целевом UI/UX;
   - внешних референсах (external/…).

3. **Запрет:** не придумывать новую архитектуру и новые блоки, если они не описаны в `MASTER_MANIFEST.json` и `MASTER_CONTEXT_*`.

---

## 2. Порядок инициализации для KiloCode

Перед выполнением задачи:

1. `LOAD` → `docs/MASTER_MANIFEST.json`
2. `LOAD` → `docs/MASTER_CONTEXT_v2.1.4_UI-REFRESH.md`
3. `LOAD` → `docs/ROADMAP_v2.1.2.md` (для проверки, не противоречит ли задача roadmap)
4. Только после этого:
   - читать доп. доки (`AGENT_ROUTING_DESIGN.md`, `MEDIA_STUDIO_DESIGN.md`, `DEPLOYMENT_*`, `progress_report_v_2_1.md`);
   - читать конкретные файлы кода по путям из `MASTER_MANIFEST.json`.

---

## 3. Как интерпретировать MASTER_MANIFEST.json

### 3.1 Раздел `blocks`

- `blocks.*.status` задаёт, **в каком состоянии находится функционал**:
  - `done` — трогать только при явном запросе пользователя.
  - `in_progress` — разрешены доработки, но с учётом описания в `MASTER_CONTEXT`.
  - `planned` — нельзя «самовольно реализовывать», только подготовка дизайна/скелета и обсуждения.

- Любые изменения в уже `done` блоках должны:
  - быть минимальными и объясняться в комментариях к diff;
  - НЕ ломать существующие end-to-end флоу и тесты.

### 3.2 Раздел `ui_layout`

- `ui_layout` — **каноническое описание UI**.
- Любой фронтенд-код должен:
  - соответствовать описанию Main Chat, левому/правому сайдбару, input bar;
  - использовать только перечисленных агентов в левой панели (`Accountant`, `Su-Chef`, `Research`, `Media Studio`);
  - не создавать “Main Chat” как отдельный проект/кнопку — стартовая страница уже является основным чатом.

### 3.3 Раздел `external_ui_references`

- `primary` репозитории (`external/lobe-chat`, `external/open-webui`) — только **как референс**, а не зависимость.
- Запрещено:
  - слепо копировать архитектуру внешних проектов;
  - тянуть новые внешние репозитории без задания пользователя.

---

## 4. Ограничения и игнорируемые пути

Агент **обязан игнорировать** содержимое путей:

- `external/*` — только читать для идей, не править и не использовать как core-код.
- `dist/*`, `node_modules/*`, `.next/*` — autogenerated артефакты.

Все изменения должны вноситься только в:

- `server/**`
- `frontend-enhanced/**`
- `shared/**`
- `docs/**`
- `.kilocode/rules/**`
- `checkpoints/**` (только по отдельному указанию пользователя).

---

## 5. Правила модификации кода

1. Любая модификация должна оформляться как **diff-предложение** (patch), а не «заливка нового файла целиком».
2. В комментарии к diff указывать:
   - какой Block/раздел затрагивается;
   - ссылку на соответствующий раздел `MASTER_MANIFEST.json`;
   - что именно улучшается (фикс, рефакторинг, реализация подпункта roadmap).

3. Запрещено:
   - добавлять новые MCP/агентов/модели без явного запроса пользователя;
   - менять порт, флаги `ENABLE_VIDEO`, RBAC, SAFE_MODE без прямого указания.

---

## 6. Взаимодействие с пользователем

Когда пользователь даёт задачу:

1. Сопоставить задачу с:
   - соответствующим блоком (`blocks.*`);
   - соответствующим агентом (`agents.list`, `agents.orchestrator.intents`);
   - соответствующим UI-элементом (`ui_layout.*`).

2. Если задача противоречит `MASTER_MANIFEST.json`:
   - не выполнять автоматически;
   - вернуть пользователю пояснение и предложить обновить `MASTER_MANIFEST`/`MASTER_CONTEXT`, если изменение осознанное.

---

## 7. Обновление манифеста и контекста

- Обновлять `MASTER_MANIFEST.json` и `MASTER_CONTEXT_*` **можно только по прямому указанию пользователя**.
- При любом крупном изменении (новый блок, смена архитектуры, переработка UI) агент обязан:
  1. сначала предложить обновлённый diff для `MASTER_CONTEXT` и `MASTER_MANIFEST`;
  2. дождаться явного подтверждения пользователя;
  3. только затем продолжать модификации кода.

---

## 8. TL;DR для KiloCode

1. **Сначала читаешь**: `MASTER_MANIFEST.json` → `MASTER_CONTEXT_v2.1.4_UI-REFRESH.md`.
2. Работаешь **в рамках блоков и UI**, описанных там.
3. Используешь `external/*` только как референс.
4. Все изменения — через diff и с привязкой к блокам.
5. Никогда не изменяешь архитектуру без обновления манифеста вместе с пользователем.

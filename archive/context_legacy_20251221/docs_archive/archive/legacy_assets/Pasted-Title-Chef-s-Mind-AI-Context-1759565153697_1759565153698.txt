Title: Chef’s Mind AI — Полный системный анализ: состояние, регрессии, метрики, изменения

Context (важно):
Health/Backup — реализованы проверки состояния и безопасное резервное копирование, автоматическая ротация, метрики успешности Model-routing/Latency — интеграция роутинга для GPT-5, Gemini, Imagen, DALL-E, замеры задержек, авто-дауншифтинг, smoke-тесты выполнены. Наблюдаются задержки (60–90s), возможная путаница роутинга моделей и контекста чатов. Нужно без правок кода снять фактическое состояние системы, собрать метрики, сверить с последними изменениями, проверить бэкапы и выдать компактный отчёт с приоритетами.

Scope / Что анализировать:

Бэкенд: /api/universal-ask, /api/media/*, /api/stt/*, /health, SAFE_MODE.

Фронтенд: работа переключателя моделей, разделение чатов/threads.

БД/кэш: доступность, размеры/индексы по «горячим» таблицам (кратко).

Логи/коммиты: последние 48 часов (что реально менялось).

Бэкапы: наличие, время создания, размер, валидность.

Tasks:

Снимок состояния

GET /health → сохранить как out/health.json (версия, внешние API, БД).

GET /api/safe/status → out/safe_status.json.

Вывести переменные режима: SAFE_MODE, REQUIRE_CONFIRM_FOR_MEDIA_JOBS, текущие ключевые конфиги роутинга/моделей (без секретов) → out/config_snapshot.md.

Изменения/коммиты (48h)

Список коммитов, изменённых файлов, краткие сообщения → out/git_changes.md.

Если есть артефакты «критических исполнений»/патчей за вчера-позавчера — перечислить файлы и кратко описать назначение.

Бэкап/восстановление

Проверить наличие последнего бэкапа (имя/время/размер) → out/backups.md.

Если эндпоинт доступен, снять свежий GET /api/db/backup с X-Confirm-Code → out/backup.dump и зафиксировать его хэш (sha256).

Маршрутизация моделей (факт)

Для ролей Chef/Accountant/Research/Media выполнить по 3 запроса с разными context.model (в т.ч. auto), с замером:
собрать ts, role, model_requested, model_used (из ответа), ttfb_ms, ttce_ms, http_code, success.

Сохранить сырые ответы out/ua_*.json и агрегат out/latency_metrics.csv.

Посчитать avg и p95 по TTFB и TTCE для каждой роли → out/latency_summary.md.
(TTFB — время до первого токена/байта; TTCE — до полного завершения ответа.)

Фронт/чаты

Зафиксировать поведение: создаются ли отдельные threadId per-чат, не «слипаются» ли истории; влияет ли выбор модели в UI на model_used в ответе. Кратко — out/ui_findings.md.

Логи и ошибки

Снять серверные логи периода замеров → out/server.log (сжатие допустимо).

В отдельный out/errors.log собрать все 4xx/5xx и stack traces за время теста.

Итоговый отчёт

Сформировать out/REPORT.md со структурой:
(A) Резюме (1 страница): главные находки, 3–5 приоритетных рекомендаций.
(B) Метрики: таблица avg/p95 по TTFB/TTCE и график (если можешь).
(C) Роутинг моделей: где UI ≠ факт; список несоответствий.
(D) Бэкап/здоровье: наличие бэкапа, версия, статусы API/БД.
(E) Недавние изменения: что делали «вчера/позавчера» и возможные регрессии.
(F) Риски и быстрые фиксы: что можно поправить без кода (конфиги/таймауты/флаги).

Deliverables (обязательно сохранить в /out):
health.json, safe_status.json, config_snapshot.md, git_changes.md, backups.md, latency_metrics.csv, latency_summary.md, ua_*.json, server.log, errors.log, REPORT.md (+ backup.dump при наличии).

Rules:

Никаких правок кода, только анализ и файлы отчёта.

Минимизируй стоимость: по 3 коротких запроса на роль, без тяжёлых генераций.

Явно выводи model_used и времена TTFB/TTCE.

Любые ошибки/таймауты — фиксируй с кодом и текстом.
